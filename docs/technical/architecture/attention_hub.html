⚡ Global Attention & Action Required Hub ​

The Attention Hub is WealthFam's centralized, sub-15ms financial command center that aggregates pending tasks, review queues, debt deadlines, and budget anomalies across the family workspace into a single actionable interface on both Web and Mobile.

3. Data Model & Statement Attend Lifecycle ​

Statement Columns ​

The PostgreSQL statements table includes:

  • is_attended BOOLEAN NOT NULL DEFAULT FALSE: Marks whether the statement has been reviewed and closed by the user.
  • closed_at TIMESTAMP WITH TIME ZONE NULL: Records the UTC timestamp of attendance.

4. RBAC & Child Role Shielding ​

Family accounts with role UserRole.CHILD are strictly shielded from household liabilities and sensitive accounts:

  • Statements, transfers, credit cards, budgets, loans, recurring suggestions, bank accounts, and CAS freshness items are forced to 0.
  • Child accounts only receive triage items for transactions assigned directly to their user ID.
  • Tested and enforced in AttentionService and verified via Test-Suite/modules/finance/test_attention_summary.py.

5. Client Integrations ​

Web-App (Vue 3 + Tailwind) ​

  • Unified Bell Notification & Action Center:
    • Replaces separate pill and bell with a single, consolidated Bell icon in the top navigation bar.
    • When $N > 0$ actions are pending, highlights in amber with a prominent badge count N.
    • When actions are completed but unread activity notifications exist, shows an indigo unread dot.
    • Clicking the bell opens a unified 2-tab dropdown (Action Required vs Activity Notifications), opening the Action tab first when items are pending.
    • Contextual Lucide icon per alert type: CreditCard, PieChart, FileText, ArrowLeftRight, Landmark, Wallet, Sparkles, Zap.
    • Scoped to active family member selector (auth.selectedMemberId).
  • Statements Page Default Hiding:
    • Attended statements are hidden by default (showAttended = false, passing is_attended=false to backend).
    • "Show Attended" pill button toggles inclusion of attended statements.
    • Marking a statement as attended immediately clears it from the active view.

Mobile-App (Flutter) ​

  • Dashboard "Pending Actions" Row:
    • Positioned between the Unified Hero Card and the Daily Spending Bar Chart.
    • Dynamically budgets +46.0 fixed overhead in screen height calculations to prevent vertical overflow on small mobile viewports.
    • Automatically collapses to zero height when all items are attended.
    • Horizontal scrollable chip row with color-coded badges and direct screen navigations.
  • Attention Hub Screen (attention_hub_screen.dart):
    • Two-Tab Structure:
      • Tab 1: Actions: Real-time aggregation of pending items (AttentionItemModel) with badge count and severity indicators (Error, Warning, Info).
      • Tab 2: Activity: Hydrated with persistent database alerts (GET /api/v1/mobile/alerts/history) merged with live WebSocket alert frames. Displays unread dots, formatted relative timestamps, and marks alerts as read (POST /api/v1/mobile/alerts/{alert_id}/read) on user tap with direct route navigation.
  • Push Notification Deduplication:
    • The redundant 60-second HTTP polling loop (/api/v1/mobile/alerts) in foreground_task_handler.dart has been removed. Foreground service and active WebSocket sockets now coordinate cleanly without firing duplicate heads-up notifications or consuming unread alert states.
  • Statements Screen Default Hiding:
    • Attended statements are excluded by default in the list.
    • "Show Attended" filter chip toggles visibility of attended records.
