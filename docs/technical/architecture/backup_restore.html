Backup & Restore (.wfam)

On this page

Full System Backup & Restore Architecture (.wfam) ​

The standalone backup module (Backend/app/modules/backup/) implements server-independent, ID-less full workspace export and priority-preserving merge restore.

.wfam Binary Container Specification (v1) ​

text
Offset   Size       Field
------   --------   -------------------------------------------------------
0        5 bytes    Magic header: b"WFAM\x01"
5        1 byte     Encryption flag:
                      0x00 = Unencrypted ZIP payload
                      0x01 = Passphrase-encrypted streaming AES-256-GCM

--- Present only when flag == 0x01 ---
6        16 bytes   Random PBKDF2 salt
22       4 bytes    PBKDF2-HMAC-SHA256 iterations (uint32 big-endian, default 600,000)
26       12 bytes   Random 96-bit base IV
38       variable   Stream of 64 KB chunks:
                      [4 bytes uint32 big-endian chunk_len]
                      [ciphertext + 16-byte GCM authentication tag]

Chunk Authentication & Streaming Security ​

  • Each 64 KB chunk derives a unique 96-bit nonce by XORing chunk_index into the last 4 bytes of base_iv.
  • Each chunk is authenticated with Associated Authenticated Data (AAD):
    python
    struct.pack(">4sBBI", b"WFAM", 1, 1 if is_final else 0, chunk_index)
    This prevents chunk reordering, silent truncation, and tampering while keeping server RAM usage flat even for multi-hundred-MB Document Vault archives.
  • Server-Key Independence: All ORM EncryptedString / EncryptedText / EncryptedNumeric columns and VaultFileCipher files are decrypted to plaintext before being zipped into the inner archive (manifest.json, data.json, files/<doc_ref>/v<N>), then wrapped with the user's passphrase. Restoring onto a server with a different SECRET_KEY, Tenant DEK, or BlindIndex key works seamlessly.

ID-Less Portable Reference Remapping ​

Database primary keys (id) and tenant_id are never relied upon across servers:

  1. Export (_RefRegistry): Every primary key is replaced with a sequential portable ref (usr_1, acc_1, cat_1, txn_1, doc_1, loan_1, goal_1, mfh_1, stmt_1, rule_1, ecfg_1, eslog_1, eg_1). Zero raw UUIDs are written to data.json.
  2. Import (id_map): Every inserted record receives a fresh uuid.uuid4(). All foreign keys and self-referencing columns (categories.parent_id, transactions.linked_transaction_id, document_vault.parent_id) are remapped via two-pass resolution.
  3. Blind Indexes & Re-encryption: Writing through ORM hybrid setters (User.email, User.pan_number, User.phone_number, Account.account_number) automatically computes new blind indexes and encrypts values under the target tenant's active DEK.

Priority-Preserving Merge Semantics ​

By default (mode="merge"), import never wipes existing data on the target server. Existing records on the new server take highest priority:

  • Tenant Settings: Existing (tenant_id, key) kept untouched; missing keys inserted.
  • Categories: Matched by (name, type); existing category preserved and mapped in id_map.
  • Accounts & 1-to-1 Extensions: Matched by (name, type) or (account_mask, type); existing account and its credit card / FD / PF / loan details are preserved and mapped in id_map.
  • Transactions: Deduplicated by content_hash or (account_id, date, amount, type, description).
  • Budgets, Expense Groups, Mutual Fund Holdings, Email Configurations: Deduplicated by natural keys so new-server state always wins.
  • Schema Evolution Tolerance: Major version is checked (1.x), missing optional fields default cleanly, unknown keys are ignored, and unknown enum values fall back safely.

Security & Operational Hardening ​

  • Role Guard: Only OWNER and ADULT roles may call /api/v1/backup/*. CHILD and GUEST receive HTTP 403.
  • Email Verification: current_user.email (normalized) must match an email in manifest.member_emails (owner or any family member); otherwise HTTP 403 is returned before any database mutation.
  • Zip-Slip & Zip-Bomb Protection: Archive entries containing .. or absolute paths are rejected; compressed upload ceiling is 512 MB and uncompressed ceiling is 1 GB.
  • DB + Filesystem Atomicity: Restored Vault files are written into freshly generated new_doc_id directories; on any failure, the DB transaction rolls back and newly created files are cleaned up without touching pre-existing files.
  • Client-Side ZK Files (WFZK01): Preserved as ciphertext with an explicit warning in manifest.warnings.

Nginx / Reverse Proxy Sizing ​

If serving WealthFam behind Nginx and backing up large Document Vaults, ensure your proxy configuration allows large .wfam uploads and sufficient request timeouts:

nginx
location /api/v1/backup/ {
    client_max_body_size 512M;
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;
}

API Endpoints ​

MethodPathDescription
POST/api/v1/backup/exportStreams a .wfam download (passphrase, encrypt=true, include_vault_files=true).
POST/api/v1/backup/inspectMultipart upload (file, passphrase); returns manifest summary & email verification status without modifying DB.
