🔒 Production Security & Resilience Hardening ​

This document outlines the security architecture and disaster recovery strategies implemented across the WealthFam microservice ecosystem.

1. 🛡️ URL-Parameter Token Deprecation & Single-Use Ticket Protocol ​

1.1 Problem Statement ​

Passing long-lived JSON Web Tokens (JWTs) in URL query parameters (e.g. ?token=eyJhbGci... or ?access_token=...) exposes authentication credentials across multiple attack vectors:

  • Browser History: Query parameters are permanently stored in client browser history.
  • Server & Ingress Access Logs: Reverse proxies, CDNs, load balancers, and Nginx write complete request URIs (including query strings) to access.log. Anyone with read access to server logs gains valid authentication credentials.
  • Referer Leaks: External links clicked or embedded media can leak query parameters to third-party servers via the HTTP Referer header.
  • Screen & Shoulder Surfing: URLs displayed in browser address bars or developer tools expose tokens in plain text.

1.2 Deprecation of Query String Tokens ​

The query parameter token dependency (token_query) has been deprecated and removed across:

  • Backend/app/modules/auth/dependencies.py (get_current_user)
  • Admin-Backend/app/main.py (WebSocket log streamer)
  • Web-App/src/api/client.ts (getDocumentDownloadUrl, getDocumentViewUrl, getDocumentThumbnailUrl)
  • Admin-Web/src/api/client.ts (getLogStreamWsUrl)

1.3 Ephemeral Single-Use Ticket Architecture ​

For media endpoints (Vault PDF downloads, inline preview iframes, and image thumbnails) where standard HTTP headers cannot always be injected directly into native HTML tags (such as <a> download links or <img> elements), WealthFam implements a cryptographic Single-Use Ticket Service:

  1. Ticket Issuance (POST /api/v1/auth/ticket):

    • The authenticated client requests a ticket using its standard Authorization: Bearer <token> header.
    • The backend generates a cryptographically random token string (wft_ + 32 bytes URL-safe base64).
    • The ticket is stored in-memory with a strict 60-second Time-To-Live (TTL), mapped to (user_id, tenant_id).
    • Returns: {"ticket": "wft_...", "expires_in": 60}.

  2. Single-Use Consumption (get_current_user_or_ticket):

    • The client invokes the target endpoint: GET /api/v1/vault/documents/{id}/download?ticket=wft_...
    • The backend validates the ticket against the active store.
    • Atomic Invalidation: Upon verification, the ticket is instantly deleted from memory (popped).
    • If the URL is intercepted, copied, or reloaded after consumption, the backend rejects it with HTTP 401 Unauthorized.
    • Any ticket not consumed within 60 seconds is automatically purged.

  3. Client-Side Blob Streaming & ObjectURL Management:

    • For Vault table thumbnails and Statement preview iframes, Web-App uses authenticated Axios requests returning Blob responses.
    • Local Object URLs (URL.createObjectURL(blob)) are assigned to <img> or <iframe> elements.
    • On component unmount or data update, URL.revokeObjectURL(url) is invoked to prevent memory leaks.

1.4 WebSocket Subprotocol Negotiation (Sec-WebSocket-Protocol) ​

Browser WebSocket implementations do not allow custom HTTP request headers (like Authorization: Bearer ...). Rather than falling back to URL query strings, WealthFam uses standard WebSocket Subprotocol Negotiation:

typescript
// Web-App WebSocket connection:
const ws = new WebSocket(url, ['wealthfam-auth', token]);

// Admin-Web log streaming connection:
const ws = new WebSocket(url, ['wealthfam-admin-auth', token]);
dart
// Mobile-App (Flutter) WebSocket connection (socket_service.dart):
_channel = IOWebSocketChannel.connect(
  Uri.parse(wsUrl),
  protocols: ['wealthfam-auth', token],
);
  • During the HTTP upgrade handshake, Web, Admin, and Mobile clients transmit: Sec-WebSocket-Protocol: wealthfam-auth, <jwt>
  • The server validates the second protocol element as the JWT, accepts the WebSocket connection with subprotocol="wealthfam-auth", and authenticates the connection without exposing tokens in the URI. Non-browser clients (such as automated probers or backend microservices) can alternatively pass standard Authorization: Bearer <token> upgrade headers.

2.2 Low-Port Binding Without Root ​

To bind privileged ports (such as Port 80) in Nginx containers without root privileges:

  1. libcap2-bin (Debian) or libcap (Alpine) is installed in the final stage.
  2. File capabilities are assigned to the Nginx binary:
    dockerfile
    setcap 'cap_net_bind_service=+ep' /usr/sbin/nginx
  3. Nginx is configured to write its process PID and temporary cache buffers to /tmp/:
    nginx
    pid /tmp/nginx.pid;
client_body_temp_path /tmp/client_temp;
proxy_temp_path /tmp/proxy_temp;

2.3 Volume Mount Ownership & Host Permissions ​

In Docker Compose (Infra/advanced-stack/docker-compose.yml and Infra/docker/docker-compose.yml), services declare:

yaml
user: "10001:10001"
  • Named Volumes (wglabz-data:/data): Docker initializes named volumes using the image layer's permissions, preserving appuser:appgroup (UID 10001) ownership automatically.
  • Linux Host Bind-Mounts: If mounting a host folder (e.g. /var/data:/data), ensure the host directory is accessible to UID 10001:
    bash
    sudo chown -R 10001:10001 /path/to/host/data

3. 💾 Automated Backup & Disaster Recovery Verification ​

WealthFam features a comprehensive automated disaster recovery routine covering the relational ledger, embedded DuckDB databases, physical Vault documents, and Brand logos.

3.1 Backup Components ​

Every backup snapshot bundles:

  1. PostgreSQL Database: Captured via pg_dump -Fc (custom compressed format, supporting parallel restoration and schema integrity).
  2. DuckDB Telemetry Database: Checkpointed (CHECKPOINT; command) to flush write-ahead logs before creating a consistent snapshot of /data/telemetry.duckdb.
  3. Document Vault: Complete compressed archive of /data/vault containing all encrypted statements, uploaded invoices, and identity records.
  4. Brand Logos: Complete compressed archive of /data/logos containing active bank and merchant brand icons.
  5. Integrity Manifest (manifest.json): JSON manifest detailing timestamps, software version (Infra/version.json), and individual SHA-256 checksums for each component.

3.2 Scheduled Automated Execution ​

Integrated directly into the backend scheduler (Backend/app/core/scheduler.py):

  • Runs automatically at 03:30 UTC every day via APScheduler.
  • Controlled via the BACKUP_ENABLED environment variable (defaults to true).
  • Automatically manages retention rotation: older backup archives exceeding the retention window (default: 7 days) are cleanly pruned.

3.3 Manual Backup & Verification CLI ​

Creating a Backup Manually: ​

bash
python Infra/scripts/maintenance/backup.py \
  --output-dir /data/backups \
  --retention-days 7

Restoring and Verifying a Backup: ​

bash
# Dry-run validation: verifies SHA-256 checksums without modifying disk
python Infra/scripts/maintenance/restore.py \
  --archive /data/backups/wealthfam_backup_20261122_075433.tar.gz \
  --dry-run

# Full live restoration:
python Infra/scripts/maintenance/restore.py \
  --archive /data/backups/wealthfam_backup_20261122_075433.tar.gz \
  --db-url postgresql://postgres:postgres@localhost:5432/wealthfam \
  --vault-dir /data/vault \
  --logos-dir /data/logos

3.4 Tamper Detection & Integrity Verification ​

Before any database table or physical directory is modified during restoration, restore.py unpacks the archive into an isolated temporary workspace and recomputes the SHA-256 hash of each component against manifest.json. If an archive has been altered or corrupted in transit, the restore process terminates immediately with ValueError: Integrity check failed, preventing corrupted state injection.

4. 🔄 Monolith Process Self-Healing & Worker Supervision ​

4.1 Problem Statement ​

When running all services together in a unified container or local development environment (Infra/orchestration/run_backend.py), a failure in any individual worker process (such as a memory limit spike in Parser, an unhandled reload error in Admin-Backend, or a developer test restart) previously caused the orchestrator's blocking join() call to exit, terminating the entire container and dropping active Web/Admin frontends.

4.2 SupervisedWorker Architecture ​

WealthFam implements an active supervision loop (SupervisedWorker) directly inside run_backend.py:

  • Crash Detection: The supervisor monitors process.is_alive() at a 1-second cadence.
  • Exponential Backoff: When a worker process exits unexpectedly (exitcode != 0), the orchestrator applies exponential backoff: $$\text{delay} = \min(\text{max_backoff}, \text{base} \times 2^{\text{crash_count} - 1})$$ Defaulting to $1.0\text{s} \to 2.0\text{s} \to 4.0\text{s} \to \dots \to 30.0\text{s}$, preventing tight CPU consumption loops if an unhandled startup bug occurs.
  • Stability Window Decay: If a service runs smoothly for more than 5 minutes (300 seconds), its crash_count resets back to 0, ensuring that rare transient crashes over days do not accumulate toward quarantine.
  • Quarantine Threshold: If a service exceeds 15 consecutive crashes without a stable period, it is quarantined to prevent continuous thrashing, logging a critical alert to the console.
  • Clean Signal Propagation: On intentional shutdown (SIGINT / SIGTERM), an atomic shutdown_event is set, gracefully killing the process tree (taskkill /F /T on Windows, proc.terminate() on Linux) without triggering resurrection loops.

5. 🗃️ Soft-Delete Governance & Topological Cascade Purge ​

5.1 Architecture & Objectives ​

To adhere to financial audit trail compliance and data minimization guidelines (e.g., GDPR, RBI data retention limits), soft-deleted records (is_deleted = True) must not accumulate indefinitely. WealthFam introduces a dedicated, decoupled governance subsystem (Backend/app/modules/governance/).

5.2 Topological Cascading Hard-Purge ​

To prevent foreign key constraint violations in PostgreSQL, the GovernanceService enforces a strict topological dependency order during permanent deletion:

  1. pending_transactions (Ingestion queue)
  2. statement_transactions (Staging items)
  3. transactions (Ledger records)
  4. statements (Parsed statement files)
  5. budgets & recurring_transactions
  6. accounts (Only purged if zero active or historical dependencies remain)

5.3 Audit Trail & Retention Logs (RetentionPurgeLog) ​

Every purge execution—whether initiated via the authenticated Admin API (POST /api/v1/governance/purge) or the CLI maintenance script (Infra/scripts/maintenance/purge_soft_deleted.py)—records an immutable audit entry in retention_purge_logs containing:

  • Retention threshold in days (default: 7 years / 2555 days)
  • Execution mode (dry_run vs live execution)
  • Detailed breakdown of purged records per table (JSONB)
  • Timestamp, status, and executing entity (executed_by)

6. ⏱️ Automatic Session Inactivity Timeout & Token Extension ​

6.1 Interactive Countdown Warning & Multi-Tab Sync ​

To prevent unattended terminal and open browser tab session hijacking:

  • Idle Monitor (useIdleTimeout.ts): Tracks pointer, keyboard, touch, and scroll interactions with debounced localStorage writes.
  • Cross-Tab Broadcast: A storage event listener ensures that activity in any open tab resets the idle timer across all other tabs in real-time.
  • 60-Second Interactive Warning (TimeoutWarningModal.vue): When inactivity reaches 14 minutes (within 60 seconds of the 15-minute limit), an accessible modal alerts the user with a live countdown and an action to "Stay Logged In" or "Log Out Now".

6.2 Seamless Session Extension (POST /api/v1/auth/refresh) ​

When the user clicks "Stay Logged In", the frontend transparently calls POST /api/v1/auth/refresh, issuing a refreshed JWT and extending the session without disrupting in-progress workflows.

6.3 Mobile Foreground Inactivity Guard ​

In Mobile-App, the BiometricGate wraps the root application tree in a pointer listener that tracks continuous foreground touch interaction, automatically locking the biometric vault if left idle on a desk for more than 15 minutes.

7. 🛡️ Python 3.14 PEP 706 Tarfile Security Compliance ​

In compliance with Python PEP 706 (integrated in Python 3.12+ and mandatory in Python 3.14+), all archive restoration routines in Infra/scripts/maintenance/restore.py invoke safe_extractall() with filter="data" (guarded by hasattr(tarfile, "data_filter"), with explicit path-traversal and symlink rejection fallback on older Python). Additionally, backup.py and restore.py pass PostgreSQL credentials strictly via the PGPASSWORD environment variable rather than command-line arguments.

8. 🔐 Public-Internet Hardening, Network Isolation & Zero-Knowledge Controls ​

8.1 Fail-Closed Secrets & Required Environment Variables ​

All production Dockerfiles (Infra/docker/Dockerfile, Backend/Dockerfile, Admin-Backend/Dockerfile) omit hardcoded default secrets and default ENVIRONMENT="production". Both Backend and Admin-Backend refuse to start in non-development environments if SECRET_KEY (<32 chars), ADMIN_SECRET_KEY (<32 chars), or ADMIN_PASSWORD is missing or left at a default value.

Required .env variables (see Infra/docker/.env.example and Infra/advanced-stack/.env.example):

  • SECRET_KEY, BLIND_INDEX_SALT, ADMIN_SECRET_KEY (32+ random hex chars each)
  • ADMIN_PASSWORD, POSTGRES_PASSWORD
  • ALLOWED_ORIGINS (explicit origin list), ALLOW_PUBLIC_REGISTRATION=false, TENANT_SEAL_STRICT=true, RATE_LIMIT_ENABLED=true

8.2 Network Segmentation & Volume Isolation ​

  • No Host Exposure of Internal Services: PostgreSQL (5432), Backend (8000), Parser (8001), and Admin-Backend (8002) are never published on host interfaces.
  • Loopback-Only Admin UI: admin-web (8080) is bound strictly to 127.0.0.1:8080 (access via SSH tunnel ssh -L 8080:127.0.0.1:8080 user@host or VPN/Tailnet).
  • Zero-Knowledge Volume Separation: In Infra/advanced-stack/docker-compose.yml, wglabz-vault is mounted only by backend (0700 permissions); admin-backend mounts only wglabz-telemetry and wglabz-logos.
  • Automatic TLS Edge Overlay: For public internet deployments, launch with Infra/docker/docker-compose.tls.yml and Infra/docker/Caddyfile (DOMAIN=app.yourdomain.com) for automatic Let's Encrypt HTTPS and HSTS.

8.3 API, Client & Mobile Security Controls ​

  • OpenAPI / Swagger Disabled in Production: All three FastAPI services (Backend, Admin-Backend, Parser) automatically disable /docs, /redoc, and OpenAPI schema endpoints (/api/v1/openapi.json and /openapi.json) when ENVIRONMENT is not development/dev/test/testing (overrideable via ENABLE_API_DOCS=true|false).
  • Rate Limiting & Session Hygiene: Sliding-window per-IP rate limiting (Backend/app/core/rate_limit.py) protects /auth/login, /auth/register, /mobile/login, and /telemetry/ingest in production. /auth/login and /auth/refresh issue HttpOnly cookies (wf_access_token, Secure=True; SameSite=Strict in prod) alongside Bearer tokens, revoke old JTIs on refresh/logout/password-change, and explicitly reject ?token= query-parameter JWTs.
  • Strict Multi-Tenant & Family RBAC: Tenant listing/updates, family member creation/role changes, Vault sync settings, and governance retention purges enforce tenant ownership and OWNER/ADULT checks. Platform-level endpoints (/brands/admin/*, /mutual-funds/benchmarks/rules*) require dedicated SYSTEM_ADMIN service auth.
  • XSS, SSRF & Parser Privacy: Web-App sanitizes all Markdown with DOMPurify (src/utils/sanitize.ts), blocks text/html and image/svg+xml in FilePreviewModal.vue (sandbox=""), and sends statement PDF passwords in JSON request bodies. Admin-Backend enforces an allowlist on /v1/endpoints/probe (no arbitrary URLs), sandboxes /v1/brands/files/* with Content-Security-Policy: default-src 'none'; sandbox, and expands PII scrubbing in sanitizer.py. Parser parses bank statements in memory (io.BytesIO) without logging raw document text.
  • Mobile Transport & Storage: Android release builds enforce HTTPS-only (usesCleartextTraffic="false", cleartextTrafficPermitted="false", allowBackup="false", and kDebugMode URL validation in app_config.dart), while android/app/src/debug/res/xml/network_security_config.xml preserves cleartext HTTP for local debug builds.

8.4 Legacy Data & Vault Encryption Backfill ​

To idempotently encrypt any pre-existing plaintext rows in PostgreSQL and legacy plaintext files/thumbnails in Vault storage (safe to re-run):

bash
# Dry-run preview
python Infra/scripts/maintenance/encrypt_legacy_data.py --dry-run

# Live backfill
python Infra/scripts/maintenance/encrypt_legacy_data.py

8. 🔐 Modular PII, Location & Zero-Knowledge Vault Encryption (RFC 0001) ​

8.1 Threat Model & Design Principles ​

Traditional financial platforms store personal identifiable information (PII) and uploaded document attachments in plaintext in PostgreSQL or filesystem directories. If an adversary, developer, hosting provider, or compromised backup acquires a database dump (pg_dump) or disk snapshot, all user credentials, emails, phone numbers, and bank statements are exposed.

WealthFam enforces a strict Zero-Knowledge at Rest model implemented via [RFC 0001](file:///c:/Users/oksbw/Desktop/Workspace/Wealthfam/Docs/Management/RFCs/0001-modular-pii-vault-encryption.md):

  • Zero Database Leakage: Sensitive columns contain only versioned AES-256-GCM ciphertexts (enc:v1:...) and non-invertible HMAC-SHA256 blind indices.
  • Zero Disk Leakage: Stored PDFs, tax documents, and thumbnails on disk (VAULT_STORAGE_PATH) are encrypted using a 64KB chunked streaming AES-256-GCM cipher with magic header b"WFENC\x01".
  • Decoupled Architecture: All cryptographic primitives are encapsulated in Backend/app/core/crypto/ via transparent SQLAlchemy custom types (EncryptedString, EncryptedText, EncryptedNumeric, EncryptedJSON).
  • High-Speed Ledger Aggregations: Financial numeric columns (amount, date, category_id, balance) remain standard typed SQL numbers to preserve sub-5ms aggregations (SUM, AVG, sparklines).

8.2 AEAD AES-256-GCM Envelope Encryption ​

All field-level encryption uses Authenticated Encryption with Associated Data (AEAD) using AES-256-GCM:

text
enc:v1:<12-byte IV in hex>:<ciphertext + 16-byte GCM authentication tag in hex>

The GCM authentication tag guarantees tamper resistance: any bit-flipping or ciphertext alteration immediately raises a DecryptionError and aborts decryption.

8.3 Thread-Safe In-Memory KeyRing & Background Job Continuity ​

To allow APScheduler background automations (such as 3:00 AM email sync and statement parsing) to operate smoothly without prompting users for a password on every cron trigger:

  • KeyRingService holds tenant Data Encryption Keys (DEKs) in volatile process RAM.
  • Keys are never persisted to disk or the database.
  • A deterministic fallback derivation using PBKDF2-HMAC-SHA256 (600,000 iterations) ensures keys can be derived in memory when background tasks process incoming webhooks or scheduled jobs.

8.4 Deterministic HMAC-SHA256 Blind Indexing ​

Because AES-256-GCM uses a random 12-byte IV for every encryption operation, standard SQL equality comparisons (WHERE email = '...') cannot match identical plaintext. WealthFam implements deterministic Blind Indexing:

python
blind_index = hmac.new(salt, plaintext.strip().lower().encode("utf-8"), hashlib.sha256).hexdigest()
  • A dedicated, isolated salt ensures blind index hashes cannot be reversed or cross-correlated with other tenants.
  • SQLAlchemy models implement custom hybrid_property with Comparator overrides:
    python
    User.email == "user@example.com"
# Compiles transparently to:
or_(User.email_bindex == BlindIndexService.compute("user@example.com"), User._email == "user@example.com")
    This enables exact-match logins and lookups with zero database plaintext leakage.

8.5 Streaming 64KB Chunked Vault Encryption at Rest ​

Physical files in the Vault (/data/vault/) are encrypted using VaultFileCipher:

  1. Magic Header: Every encrypted file begins with 8 magic bytes: b"WFENC\x01" followed by a 1-byte IV length indicator.
  2. Chunked Streaming: Files are encrypted and decrypted in 64KB chunks with per-chunk IV derivation and 16-byte authentication tags. Memory consumption is strictly bounded to $\le 128\text{ KB}$ regardless of whether the document is a 50KB receipt or a 500MB video/tax archive.
  3. Transparent Ephemeral Decryption: For tools like PyMuPDF statement parsers that require a physical file path, VaultService.prepare_readable_file_path() creates a temporary decrypted file in /tmp/ and dispatches a background task to cleanly delete it immediately after processing.

8.6 Zero-Retention Raw Message Storage Policy ​

To minimize attack surfaces, WealthFam adheres to strict zero-retention principles for raw communication bodies:

  • email_sync_item_logs.raw_content is stored as NULL after extraction.
  • Legacy raw bodies were permanently scrubbed via migration j1e2f3g4h5i6.
  • unparsed_messages table was truncated.
  • Statement.email_body is encrypted at rest using EncryptedText (protecting statement unlock password hints).
  • Ephemeral triage items preserve raw_message only temporarily in-memory or in triage state until confirmed or dismissed by the user.

8.7 Telemetry & Log Ciphertext Redaction ​

The telemetry pipeline (AsyncHttpLogHandler and scrub_text()) was upgraded to identify versioned ciphertexts using regular expressions (\benc:v\d+:[0-9a-fA-F]+:[0-9a-fA-F]+\b) and replace them with [REDACTED_CIPHERTEXT] alongside emails, phone numbers, PANs, JWTs, and UUIDs before logs are forwarded to Admin telemetry.
