🏗️ System Infrastructure ​

The WealthFam ecosystem is supported by a set of robust orchestration and repair utilities designed to maintain system health and automate complex management tasks.

🛠️ Management & Orchestration ​

⚙️ System Orchestration ​

Infra/orchestration/run_backend.py manages the lifecycle of Backend (:8000), Parser (:8001), Admin-Backend (:8002), Web-App (:5173), and Admin-Web (:5174), initializing both /data/logos and /data/vault (or <workspace>/data/{logos,vault} locally) and running DuckDB recovery/vacuum before boot.

🧹 Database Maintenance, /data Consistency & Automated Backups ​

PostgreSQL vacuuming is handled natively by PostgreSQL. Embedded DuckDB files (ingestion_engine_parser.duckdb and telemetry.duckdb) use 4-slash absolute duckdb:////data/... URLs inside Linux Docker containers and are maintained by Infra/scripts/maintenance/recover_db.py (WAL recovery + CHECKPOINT) and vacuum_db.py (Parquet export/re-import compaction).

  • /data-Aware Config Resolution: Backend/app/core/config.py and Admin-Backend/app/core/config.py automatically resolve VAULT_STORAGE_PATH and LOGOS_STORAGE_PATH to /data/vault and /data/logos in Linux containers (including normalizing relative data/... overrides under /data) and fall back to <workspace>/data/... locally. Parser/config.py guards its duckdb:///data/ rewrite with os.name != "nt" to prevent local Windows runs from redirecting into C:\data.
  • Automated Disaster Recovery Backups: Managed by Infra/scripts/maintenance/backup.py and restore.py. Snapshots cover PostgreSQL (pg_dump -Fc), DuckDB (CHECKPOINT + copy), /data/vault, /data/logos, and produce a SHA-256 integrity manifest (manifest.json). Automatically triggered daily at 03:30 UTC via APScheduler with configurable retention rotation. See Security & Resilience Hardening for complete details.

🔒 Core Security & Non-Root Container Execution ​

All container images run strictly under unprivileged users (appuser:10001 or nginx:101). Nginx writes PID and cache files to /tmp/, and low-port binding is handled via file capabilities (cap_net_bind_service=+ep). URL-parameter JWTs are deprecated across all services, replaced by secure HTTP headers, ephemeral single-use tickets (POST /api/v1/auth/ticket, 60s TTL), and WebSocket subprotocol negotiation (Sec-WebSocket-Protocol: wealthfam-auth). Complete architecture is documented in Security & Resilience Hardening.

🌐 Nginx Reverse Proxy Topology (Infra/docker/nginx.conf) ​

  • Port 80 (Client Ingress): Serves Web-App at / and proxies /api (:8000), /ws/ (:8000), and write-only anonymous /telemetry/ (:8002/v1/telemetry/). Consumer ingress has zero /parser/ exposure; Backend communicates with Parser (PARSER_SERVICE_URL) and Admin-Backend (ADMIN_SERVICE_URL) internally.
  • Port 8080 (Dedicated Admin Ingress): Port-isolated server serving Admin-Web at / and proxying /admin-api/ (including WS /admin-api/logs/stream) to Admin-Backend (:8002/v1/).

🩹 Recovery Tools & Startup Self-Healing ​

  • Schema Migrations: Run programmatically on startup via Alembic, resolving and recovering schema state automatically.
  • Vault Path Self-Healing: Backend/app/main.py executes VaultService.heal_legacy_paths non-blockingly on startup (complemented by runtime resolution in VaultService.resolve_file_path) to rewrite stale /app/data/vault/... and legacy DocumentVault/DocumentVersion paths only when the target file is verified on disk under VAULT_STORAGE_PATH.
  • Zero-Config MultiFernet Key Rotation: CryptoUtils utilizes cryptography.fernet.MultiFernet with automatic fingerprint caching. New encryptions use SECRET_KEY, while decryptions check SECRET_KEY, any configured PREVIOUS_SECRET_KEYS, and automatically fall back to historical default keys (CHANGE_THIS_TO_A_SECURE_SECRET_IN_PRODUCTION, CHANGE_THIS_IN_PROD). Users transitioning from defaults to secure keys never face decryption failures or need to memorize default keys.
  • Validation Log & Error Hygiene: HTTP 422 error handlers in Backend/app/main.py strictly sanitize error output (loc, msg, type), preventing sensitive request payloads and credentials from appearing in logs or response bodies.
  • Intuitive CORS Origin Normalization: Incoming ALLOWED_ORIGINS are cleaned of whitespace and trailing slashes (/), preventing subtle cross-origin blockages, and default safely to * (allow_origin_regex=".*") when omitted.

🗺️ Logical Layout ​

Infrastructure is decoupled from application logic to ensure that deployment environments can be swapped or hardened without affecting the core financial engine.

  • Environment Sync: Synchronized variable management across production/demo.
  • Microservice Decoupling: Standalone service containers.
  • Nginx Ingress: Centralized traffic management.

🛠️ Deep How-To: Database Migration & Recovery ​

Schema Migrations (Alembic) ​

Ecosystem schema changes are handled automatically via Alembic. If a migration is out of sync or needs to be forced manually:

  1. Connect to the backend terminal or container.
  2. Run the manual migration command:
    bash
    alembic upgrade head

How to Perform a Full Ecosystem Backup ​

To capture a consolidated, cryptographically-verified snapshot of the PostgreSQL ledger, DuckDB telemetry, Document Vault, and Brand Logos:

bash
# Full ecosystem backup (creates .tar.gz with SHA-256 manifest.json)
python Infra/scripts/maintenance/backup.py --output-dir /data/backups

# Verify integrity and dry-run restore
python Infra/scripts/maintenance/restore.py --archive /data/backups/<backup_file>.tar.gz --dry-run
